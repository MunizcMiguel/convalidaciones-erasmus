## Learning objectives

Students who successfully complete the course will acquire knowledge of the main software and communication layers of modern computer systems, with particular attention to the relationship between operating systems, system programming, concurrency, and network communication.

In particular, the course aims to provide knowledge of the following thematic areas:

- structure and functions of modern operating systems, with particular reference to Unix and Unix-like systems;
- use of the Unix shell and of the main abstractions provided by the operating system, such as processes, threads, files, directories, file descriptors, and system calls;
- concurrent programming in C using processes, POSIX threads, mutexes, condition variables, semaphores, and synchronization primitives;
- inter-process and distributed communication, with particular reference to shared-memory communication, message passing, and sockets;
- process and thread scheduling and criteria for evaluating scheduling algorithms;
- fundamentals of computer networks, OSI and TCP/IP models, and data link, network, and transport layers;
- network protocols and technologies relevant to distributed applications: Ethernet, Wi-Fi, IPv4, IPv6, UDP, and TCP;
- fundamentals of network security, including cryptography principles, authentication, digital signatures, and TLS.

The course provides theoretical and practical tools to understand how software applications interact with the operating system and the network, and to design concurrent and distributed applications using an engineering-oriented approach.

## Skills

Students who successfully complete the course will be able to apply the acquired knowledge to the design, implementation, and analysis of system-level, concurrent, and distributed applications.

In particular, students will be able to:

- use the Unix shell and basic development tools to compile, execute, and test C programs;
- design and implement C programs that use Unix/POSIX system calls for managing processes, threads, signals, files, directories, and sockets;
- identify concurrency problems, shared-resource access issues, synchronization needs, and waiting conditions, selecting suitable primitives to address them;
- design simple client-server application protocols and implement them using sockets;
- analyze the advantages, limitations, and application contexts of different communication and synchronization mechanisms;
- interpret the behavior of the main network protocols and evaluate the implications of protocol choices in terms of reliability, performance, and security;

## Teaching methods

The course consists of 60 hours in total, indicatively divided into 45 hours of lectures and 15 hours of practical sessions.

Lectures introduce theoretical concepts and reference models, with examples related to Unix/POSIX operating systems, concurrent programming, file systems, networks, and security. Practical sessions are mainly devoted to the design, writing, compilation, and execution of C programs.

Lectures and practical sessions are held in person. During practical sessions, students are expected to use their own laptop, preferably configured with the working environment indicated by the instructor. To this aim, a virtual machine is provided to standardize the development environment.

Individual work includes studying the textbooks and slides, reviewing examples discussed in class, independently solving the proposed exercises, and completing the individual project.

Teaching material, exercise sheets, solutions, project specifications, instructor communications, and any lecture recordings are made available through the course Microsoft Teams platform and/or through the course web page.

## Assessment methods

The exam consists of:

1. completion of an individual project, including its discussion with the instructor;
2. oral exam on the course topics.

The project consists of implementing a concurrent and distributed application in C, running on a Unix or Unix-like system and compliant with the specifications provided by the instructor. The project must be completed individually. The submission includes the source code and a concise report, with a maximum length of 2 pages, describing the main design choices. The project discussion takes place before the oral exam and includes the compilation of the source files using the tools indicated by the instructor, the execution of the application to verify compliance with the specifications, the analysis of the source code and report, questions about design choices, with particular reference to concurrency, synchronization, socket communication, file management, and error handling. The assessment of the project takes into account:

- functional correctness of the project and compliance with the specifications;
- quality of the implementation, with particular attention to robustness, error handling, correct use of Unix/POSIX primitives, and absence of concurrency issues;
- ability to discuss and justify design choices;

The oral exam assesses knowledge and understanding of the course topics, the ability to apply them to concrete problems, and the ability to justify technical choices. Questions may concern both theoretical contents and examples or exercises discussed in class. The assessment of the oral exam takes into account:

- mastery of the theoretical and applied topics assessed during the oral exam;
- clarity of exposition and appropriate use of technical language.

To pass the exam with a mark of at least 18/30, students must demonstrate at least sufficient knowledge of the main course topics, be able to describe the behavior of fundamental primitives and protocols, and submit a project that compiles, runs, and substantially complies with the specifications. Marks above 25/30 are awarded when students demonstrate good mastery of the connections between theory and practice, discuss the project confidently, and correctly justify their implementation choices. A mark of 30/30, with possible honors, requires excellent knowledge of the topics, the ability to critically connect the different thematic areas, a robust and well-argued project, autonomy of judgment, and particularly clear exposition.

## Assessment criteria of behaviors

The expected behaviors are assessed through the individual project, the code discussion, and the oral exam. In particular, the instructor evaluates whether the student:

- correctly identifies the design problems posed by the specifications;
- selects primitives and data structures that are coherent with the problem;
- recognizes issues such as race conditions, deadlocks, busy waiting, partial sends/receives, concurrent management of shared resources, and error conditions;
- clearly communicates how the proposed solution works;
- shows autonomy in connecting the project work with the theoretical topics of the course.

## Assessment criteria of knowledge

Knowledge is assessed mainly through the final oral exam, in which students must demonstrate mastery of the concepts covered during the course and the ability to connect the different thematic areas.

During the oral exam, students may be asked to:

- define and explain fundamental concepts related to operating systems, processes, threads, file systems, networks, and security;
- describe the behavior of Unix/POSIX primitives and network protocols;
- compare alternative solutions, for example processes versus threads, different synchronization mechanisms, connection-oriented versus connectionless protocols, or scheduling algorithms;
- discuss examples covered in lectures, practical sessions, or the individual project.

The practical sessions allow students to self-assess their understanding of the topics, but they do not constitute independent graded mid-term assessments unless otherwise communicated by the instructor.

## Assessment methods

Skills are assessed through the individual project and the related discussion with the instructor.

The project requires students to implement, in C, a concurrent and distributed application running on a Unix or Unix-like system. The application consists of client and server components communicating through sockets. The project discussion assesses:

- correct compilation and execution of the application;
- compliance with the assigned functional specifications;
- quality of the design choices concerning concurrency, synchronization, client-server communication, resource management, and error handling;
- the student's ability to explain and justify the submitted code;
- consistency between the submitted report, the actual implementation, and the answers provided during the discussion.

The oral exam also assesses the student's ability to analyze problems related to the design, implementation, and use of operating systems, concurrent/distributed applications, and computer networks, and to propose technically sound solutions.

## Teaching methods

Through the course, students develop transversal skills and professional behaviors useful in system software engineering:

- autonomy in analyzing technical specifications and choosing implementation strategies;
- attention to correctness, robustness, and error handling in system programming;
- problem-solving skills for open-ended problems, where the mechanical application of a single primitive is not sufficient;
- ability to orally justify design choices;
- habit of experimentally verifying code behavior in a Unix or Unix-like environment.

## Prerequisites

Basic knowledge of C/C++ programming and computer architecture is required.

In particular, to follow the course effectively, students should be able to use control structures, functions, pointers, arrays, strings, structs, and dynamic memory allocation, and should understand fundamental concepts related to CPUs, registers, memory, memory hierarchy, and input/output devices.

Previous knowledge of Unix/POSIX programming or computer networks is not required: these topics are introduced and developed during the course.

## Contents

Operating systems and Unixprogramming:

- introduction to operating systems: abstraction, resource management, basic computer architecture, user/kernel mode, and system calls;
- Unix operating system: general architecture, POSIX standard, Unix shell, basic commands, permissions, users, and privileges;
- processes and threads: creation, termination, states, signals, differences between processes and threads, and use of the POSIX pthread library;
- concurrency and synchronization: race conditions, mutexes, condition variables, semaphores;
- inter-process communication and sockets: shared-memory and message-passing models, client-server communication, and socket programming;
- files and file systems: files, directories, metadata, file descriptors, file operations, physical organization of Unix file systems;
- process and thread scheduling: goals, metrics, and main families of algorithms.

Computer networks:

- network communication problems and general Internet architecture;
- protocol stack, layers, services, and interfaces; OSI and TCP/IP models;
- physical and data link layers: transmission media, framing, error control, medium access, Ethernet, and Wi-Fi;
- network layer: packet switching, forwarding, routing, IPv4, IPv6, and NAT;
- transport layer: ports, UDP, TCP.

Network security:

- security properties;
- basic concepts of symmetric and asymmetric cryptography;
- authentication, digital signatures, digital certificates;
- the TLS protocol.

Practical sessions and project:

- review of C programming and use of the Unix shell;
- exercises on processes, threads, synchronization, IPC, sockets, file operations, and multithreaded servers;
- individual project on a concurrent and distributed client-server application in C.

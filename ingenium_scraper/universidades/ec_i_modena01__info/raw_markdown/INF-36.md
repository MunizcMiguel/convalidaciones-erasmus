## Contents

The course will provide the main theoretical technological and applicative knowledge of the following phases in which the life cycle of a software system can be divided: requirement specifications, design, implementation, testing, deployment and maintenance. In particular: 1. Requirement specifications [2.5 CFU] Theoretical part: The specific goals of the requirements, the expected inputs and how to create specifications. Application part: Using the UML use case diagram for the representation of the requirements. 2. Design [4.5 CFU] Theoretical part: The objectives of the planning phase, the high-level design definition and detail. Examples of architectural styles. Functional decomposition. Object Relational Mapping: definition and issues. Defining the design quality characteristics. Introduction of metrics for software evaluation. Definition of cohesion and coupling of software modules. Application part: Use of UML diagrams for the description of the software. ORM: JPA and Hibernate. Use of design patterns for software design. 3. Implementation, testing [1.5 CFU] Theoretical part: Defining what it is meant by good planning and identification of best practices. Software refactoring. Software testing and code inspection. Survey of several testing techniques (Path Analysis, Boundary values analysis, ...). Application part: Junit: the framework for testing Java programs Overview of basic techniques of defensive programming Maven and Git programming support, and software management. 4. Distribution and Maintenance [0.5 CFU] Theoretical part: Description of the main problems associated with configuration management and post-production software. Types of software licenses. 5. AI-Native Software Engineering [1.0 CFU] Theoretical Part: Use of LLMs and agents across the different phases of the software development lifecycle. Opportunities, limitations, and risks of AI-generated code. The role of human verification. Practical Part: Demonstration of AI coding assistants for software generation, comprehension, modification, refactoring, and testing.

## Learning objectives

Providing the fundamental knowledge of the models, languages and technologies for requirements specification, design, implementation, testing, deployment and maintenance of software systems.

## Teaching methods

The subject is taught through lectures that take advantage of the use of slide made available to students through the dolly platform and laboratory practical lessons. The lectures are intended to provide a "theoretical" knowledge base of the subject. For each topic covered are also made available through the dolly platform some details (scientific articles, specialized web sites) for those who further deepen the topics. The practical lessons are intended to introduce some specific software tools.

## Other information

1. Knowledge and understanding: The lectures will provide the students with the ability to know and understand the major technology, scientific and application-related trends in the software engineering. 2. Ability to apply knowledge and understanding Through laboratory practical classes the students will describe the specific requirements and design of a software system. The students will be able to design software according to patterns consolidated and available in the literature. 3. Making judgments The students will be able to assess whether a program has been specified, designed and developed in compliance with well-known, standard quality methodologies. 4. Communication skills The studentd will be able to gather and describe the technical specifications of a software. 5. Learning skills The student will achieve the knowledge and the ability to perform further and complete investigations on the issues of software design.

## Assessment methods

Learning is verified through a written test and a report. The written test lasts two hours and consists of - 3-4 open questions to verify the notional part of the course. This part affects about 30% of the overall evaluation; - exercises for the software application design (a problem is provided in textual format and it is required to design the supporting software application through use case diagrams, class diagrams, sequence diagrams, package diagrams, activity diagrams. pattern in application development This part accounts for about 55% of the overall evaluation; - testing exercises (a function is provided and asked which tests to perform). This part accounts for about 55% of the overall evaluation. The individual report is intended to describe a software product in detail. The student can describe the application developed in the Object-oriented Programming exam. The description must contain the specification of the requirements, and a description of the project through appropriate UML diagrams. The software design must be appropriately reworked by introducing appropriate design patterns. The paper is evaluated according to criteria of precision and correctness (25%), completeness in design and use of patterns (50%); wow effect (25%).
